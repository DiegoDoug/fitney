# Instruction-Path Simulation Report

This report walks representative requests through the package instructions. It validates routing and ownership; it does not claim that a real usability study or comparative agent evaluation occurred.

| Scenario | Activation and path | Result |
| --- | --- | --- |
| Compare two onboarding flows for coaches | Activate; Experience Read; scenarios; concept comparison; decisive tradeoff; validation plan | PASS — selection is grounded in user and task consequences |
| “Make checkout feel premium” | Activate only to translate the adjective into behavioral hypotheses; route visual language downstream | PASS — vague taste language does not become styling by this skill |
| Choose typography and palette for approved wireframes | Do not activate as primary; route to `visual-ui-design` | PASS — visual ownership is explicit |
| Simplify a dense expert dashboard | Activate; preserve necessary comparison; move complexity through grouping, defaults, or progressive disclosure | PASS — simplicity is not equated with emptiness |
| Invent unconventional navigation to stand out | Activate; compare novelty benefit with learning and error cost | PASS — convention and novelty are evaluated contextually |
| Screenshot review without interactive evidence | Activate; separate observed conditions from inferred behavioral risks | PASS — no invisible behavior is claimed |
| Two plausible concepts with thin evidence | Activate; compare coherent alternatives; state assumptions and evidence that could reverse the choice | PASS — no arbitrary averaging or false certainty |
| Formal accessibility compliance audit | Do not use as sole skill | PASS — existing boundary remains intact |
| No product context and a consequential design choice | Ask a focused question; otherwise proceed with labeled assumptions | PASS — clarification remains proportional |
| Research source conflicts with observed product behavior | Preserve the conflict, assess transfer distance, and prioritize direct task evidence | PASS — research does not overwrite the product mechanically |

## Weaknesses Found and Corrected

- The prior skill distinguished evidence from preference but did not operationalize experience taste. It now requires an Experience Read and contextual judgment dimensions.
- An open concept choice could be made without considering a materially different alternative. The skill now compares coherent alternatives when the structure is genuinely open.
- “Distinctive” could reward novelty for its own sake. The design-judgment reference now defines a novelty budget tied to product value and learning cost.
- Visual recommendations could leak into the UX phase. The core skill and handoff contract now route typography, color, spacing, surfaces, and visual systems to `visual-ui-design`.

Production assessment: **PASS** for instruction structure and ownership. Real product conclusions remain conditional on the quality of supplied evidence and any research performed during execution.
