# Web

Prefer semantic native HTML behavior and progressive enhancement. A website may be visually platform-influenced while still needing web-native focus, keyboard, hover, pointer, history, URL, responsive, and accessibility behavior.

Define breakpoints by content pressure rather than device brand. Specify reflow, priority, overflow, navigation changes, density changes, and input adaptation. Preserve visible focus, logical DOM/order, zoom and text resizing, reduced motion, high contrast/forced colors, and predictable link/button semantics.

Use headless or styled component libraries as implementation references after semantics and visual treatment are decided. Never let an available library component choose the product architecture.
