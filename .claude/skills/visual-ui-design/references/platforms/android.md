# Android and Material

Use current Android design guidance and Material documentation for platform-specific claims.

Choose whether the product is Material-native, Material-adapted, or merely Material-influenced. Preserve Android navigation, system bars/insets, back behavior, window classes, accessibility, typography scaling, and component semantics. Consider dynamic color only when brand and OS support make it appropriate.

Design for varied screen sizes, densities, input modes, foldables, and system configurations. Do not make one fixed phone canvas the system. Validate touch targets, TalkBack order/names, font scaling, contrast, dark theme, edge-to-edge layouts, localization, and adaptive navigation.
