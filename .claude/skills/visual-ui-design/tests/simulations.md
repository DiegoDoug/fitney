# Simulation suite

| Scenario | Activate? | Expected route | Critical invariant |
|---|---:|---|---|
| “Apply a high-fidelity system to these approved wireframes” | Yes | upstream artifacts -> full spec | Preserve structure |
| “Make this iPad coaching app look native” | Yes | intake gaps -> iOS/iPadOS | Record native/adapted level |
| “Create the checkout user flow” | No/compose | user-flow skill first | Do not replace flow work |
| “Implement this exact Figma screen in React” | Usually compose | implementation primary; visual skill only if decisions missing | Do not redesign unasked |
| “Make it minimal” with no context | Yes | focused intake | Do not default to white cards |
| “Make it premium” for a government benefits form | Yes | translate adjective -> Design Read -> constrained direction | Premium must not override trust or access |
| “Make it look like Linear” | Yes | deconstruct reference -> extract relevant principles -> product-specific thesis | Do not clone the reference |
| Design a high-fidelity workout dashboard | Yes | artifact mode -> rendered design -> critique -> corrected render | Markdown alone is incomplete |
| Same prompt applied to a hospital console and fashion editorial | Yes | separate dials, thesis, and signature move | Outputs must not converge on one house style |
| Existing UI is correct but generic | Yes | anti-pattern review -> distinction budget -> rendered iteration | Add one earned signature, not decoration everywhere |
| Dense hospital dashboard asks for huge whitespace | Yes | conflict resolution | Preserve required monitoring density |
| Existing app screenshots contradict approved IA | Yes | conflict surfaced | Do not silently reconcile |
| Dribbble shot offered as accessibility proof | Yes | source policy | Inspiration is not evidence |
| Target OS version unknown for an SF Symbol | Yes | iOS reference + verify/ask | No unsupported native claim |
| No access to a pattern database | Yes | continue with higher-tier sources | Disclose only if material |
| Existing visual system gains a new product area | Yes | read Design Memory -> classify -> extend or request superseding decision | No silent drift or competing state file |
| Search for a suitable pattern under limited context | Yes | local knowledge search -> inspect matches -> source policy | Search rank is not design authority |
| Native iPad interface with keyboard and resizable windows | Yes | iOS/iPadOS reference -> Apple attachment -> official verification | Do not scale an iPhone composition |
| Candidate skill produces a polished but generic result | Test path | comparative taste regressions -> correct instructions | Expression cannot trade away task clarity |

Expected production status: PASS WITH CONDITIONS until repeated comparative runs show that outputs vary coherently with context and improve after critique. Rendered design requests must receive rendered artifacts and at least one critique-and-correction pass. Live external sources are conditional and must be re-verified when used.
