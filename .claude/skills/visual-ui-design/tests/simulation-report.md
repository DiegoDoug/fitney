# Instruction-Path Simulation Report

This report walks representative requests through the package instructions. It validates routing and invariants; it does not substitute for comparing rendered outputs from repeated real runs.

## Weaknesses Found and Corrected

- A direction-only Markdown artifact could previously satisfy a high-fidelity design request. `artifact-modes.md` and the core output rule now require a rendered artifact.
- “Anti-slop” guidance could harden into another house style. `anti-patterns.md` now treats patterns as contextual diagnostic signals and records valid exceptions.
- Numeric design dials could imply fake precision. `taste-and-calibration.md` now uses named anchors and treats dials as settings rather than scores.
- Distinction could become decoration everywhere. The package now requires a limited signature move plus a restraint rule.
- A valid first render could pass without visual iteration. Rendered work now requires at least one critique-and-correction pass.
- Persistent design decisions could fragment across third-party state files. The Design Memory attachment now keeps continuity inside the canonical visual artifact.
- Reference discovery depended on manually scanning a large registry. The local retrieval script now narrows maintained guidance without network or package dependencies.
- Apple guidance was present but shallow. The platform attachment now routes device, input, presentation, adaptation, state, and evidence checks while keeping official Apple sources authoritative.
- Taste improvements lacked a stable comparison harness. The regression attachment and prompt set now test contextual variation and guard against polished generic output.

Production assessment: **PASS WITH CONDITIONS** until repeated comparative runs demonstrate that different product contexts produce materially different, stronger rendered outputs. Package structure, routing, and static validation pass.
